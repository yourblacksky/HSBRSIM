# 行为克隆 + 强化学习微调：理论推导与训练策略

## 1. 问题定义

在酒馆战棋 RL 训练中，直接使用稀疏奖励（仅终局排名）从零训练 PPO 智能体遭遇**冷启动失败**：
500k 步训练后排名始终为第 8，模型从未收到正向奖励信号。

根本原因：动作空间 |A| = 50，对局长度 T ≈ 50-100 步。随机策略在一局中发现正向奖励序列的概率趋近于零——探索空间太大，稀疏奖励无法回溯传播。

## 2. 专家策略 π*

### 2.1 启发式定义

当前引擎中的 Q-score 贪心启发式（`Game._auto_player_turn`）：

**状态评估**：对任意棋盘 B，定义 Q-score：

```
Q(B) = Σ_{m ∈ B} (atk(m) + health(m) + aura_atk(m) + aura_health(m))
```

本质是棋盘总战斗属性之和，隐式建模了"站场能力"。

**决策规则**：

1. **购买优先**：遍历酒馆中所有可负担的随从，计算购买并打出后的 Q(B')，选择使 Q 最大化的候选
2. **替换规则**：若棋盘已满（7个），且存在 `Q(candidate) - Q(weakest) > 0`，则卖掉最弱者买入新随从
3. **升级酒馆**：无可购买随从且金钱 ≥ 升级费用时升级
4. **刷新酒馆**：以上均不可行且金钱 ≥ 1 时刷新
5. **结束回合**：金钱为 0 或超过 30 次尝试后结束

该策略纯贪心、无前瞻（不考虑对手、不考虑战斗概率），但提供了合理的基线表现——在纯启发式对局中能产生胜者。

### 2.2 专家动作映射

RL 动作空间 `Discrete(50)` 编码为：

| 动作 ID | 语义 |
|---------|------|
| 0-6 | 购买酒馆第 N 个实体 |
| 7-13 | 出售棋盘第 N 个随从 |
| 14-23 | 打出手牌第 N 张 |
| 24 | 刷新酒馆 |
| 25 | 升级酒馆 |
| 26 | 冻结/解冻酒馆 |
| 27 | 使用英雄技能 |
| 28 | 结束回合 |
| 29 | 获取 Buddy |
| 30 | 重排棋盘 |

启发式策略的选择——购买特定酒馆随从、出售最弱随从、升级、刷新——可直接映射到上述动作空间。具体映射规则：

- `buy_minion(player, candidate)` → action = BUY_OFFSET + tavern_index(candidate)
- `sell_minion(player, weakest)` → action = SELL_OFFSET + board_index(weakest)
- `play_minion(player, card)` → action = PLAY_OFFSET + hand_index(card)
- `refresh_tavern(player)` → action = 24 (REFRESH)
- `UpgradeTavern(player)` → action = 25 (UPGRADE)
- 回合结束 → action = 28 (END_TURN)

专家策略不使用：冻结(26)、英雄技能(27)、Buddy(29)、重排(30)。

## 3. 行为克隆 (Behavior Cloning)

### 3.1 目标函数

给定专家策略 π*，收集数据集 D = {(s_i, a_i*)}，其中 a_i* ~ π*(s_i)。

行为克隆目标是最小化负对数似然：

```
L_BC(θ) = -E_{(s,a*) ~ D}[log π_θ(a* | s)]
```

其中 π_θ 是参数为 θ 的随机策略网络（与 PPO 共享同一 Actor 网络）。

等价于监督学习的交叉熵损失——分类任务，|A| = 50 类。

### 3.2 数据收集策略

**关键设计选择**：专家数据应覆盖多样化的游戏状态。

- **对局数**：N = 1,000-5,000 场完整对局
- **英雄多样性**：每局随机选择 8 个英雄，收集所有 8 个玩家的动作
- **状态覆盖**：不同酒馆等级(1-6)、不同种族组合、不同游戏阶段
- **数据量估算**：平均每局 ~80 步，8 个玩家 → ~640 (s,a) 对/局 × 5000 局 ≈ 3.2M 样本

**重要**：不应只收集第一名/获胜者的轨迹。所有玩家的决策都基于同一 Q-score 启发式，每个 (s,a) 对都是专家在当前状态下的理性选择。使用所有玩家的数据增加了状态多样性。

### 3.3 为什么 BC 能解决冷启动

- BC 提供有监督的学习信号——每一步都有明确的目标动作，无探索问题
- BC 初始化后的策略已经具备"合理购买→提升战力→赢得战斗→存活更久→更高排名"的行为链
- 因此 RL 微调阶段，智能体从一开始就能偶尔赢下战斗，收到正向奖励
- 正向奖励通过 PPO 的价值函数回溯传播，逐步改进策略

### 3.4 BC 的局限性

- **分布偏移 (Distribution Shift)**：BC 策略在自博弈时访问的状态分布与训练分布不同，误差累积
- **上限受限**：BC 只能逼近专家水平，无法超越（专家 = Q-score 贪心启发式）
- **不学习反制策略**：启发式不考虑对手策略，BC 策略也不会

这正是 RL 微调要解决的问题。

## 4. RL 微调 (PPO Fine-tuning)

### 4.1 初始化

```
θ_0 = θ_BC     # 从 BC 训练的策略权重开始
φ_0 = random    # 价值网络随机初始化（或也从 BC 热身）
```

### 4.2 目标函数

标准 PPO clipped surrogate objective：

```
L_CLIP(θ) = E_t[min(r_t(θ) · A_t, clip(r_t(θ), 1-ε, 1+ε) · A_t)]

r_t(θ) = π_θ(a_t | s_t) / π_θ_old(a_t | s_t)
```

其中优势函数 A_t 由 GAE 估计，价值网络 V_φ 通过 MSE 损失训练：

```
L_VF(φ) = E_t[(V_φ(s_t) - R_t)²]
```

### 4.3 奖励结构（稀疏 + 效率惩罚）

| 信号 | 值 | 时机 |
|------|-----|------|
| 第 1 名 | +20 | 终局 |
| 第 2 名 | +10 | 终局 |
| 第 3 名 | +5 | 终局 |
| 第 4 名 | +2 | 终局 |
| 第 5 名 | -2 | 终局 |
| 第 6 名 | -5 | 终局 |
| 第 7 名 | -10 | 终局 |
| 第 8 名 | -20 | 终局 |
| 战斗胜利 | +1.0 | 每回合战斗后 |
| 战斗失败 | -0.5 | 每回合战斗后 |
| 平局 | +0.2 | 每回合战斗后 |
| 淘汰对手 | +2.0 | 每回合战斗后 |
| 存活 | +0.05 | 每回合开始时 |
| 无效动作 | -0.05 | 动作后 |
| 重排 | -0.02 | 动作后 |
| 回合动作超限 | -0.10 | 强制结束回合时 |
| 每步 | -0.002 | 每个动作后 |

**设计原则**：
- **稀疏主导**：终局排名 ±20 是最大信号，压倒所有中间奖励
- **战斗引导**：每回合战斗结果提供中等频率的中间信号（~10-15次/局）
- **效率惩罚**：每步微小的负奖励抑制无意义动作，鼓励高效结束回合

### 4.4 对手配置

RL 微调阶段使用**随机启发式对手**（非轨迹对手）：
- 7 个对手每局随机选择英雄
- 均使用 Q-score 贪心启发式
- 训练分布≈测试分布，无过拟合问题

### 4.5 为什么 BC→RL 序列有效

1. **BC 提供可行解区域**：θ_BC 已经在参数空间中靠近好的局部最优
2. **RL 突破上限**：PPO 可以学习启发式不具备的能力——反制定位（taunt 前置）、资源规划（存钱升级 vs 立即购买）、风险权衡
3. **避免毁灭性遗忘**：PPO 的 clip 机制 + 适度的 KL 惩罚防止策略偏离 BC 初始化太远
4. **渐进式改进**：因为已能赢一些战斗，奖励信号足够稠密以驱动优化

## 5. 实验设计

|------|-----|
| 训练对局 | 2,000-5,000 |
| 数据量 | ~1.3-3.2M (s,a) 对 |
| 网络结构 | 与 PPO Actor 相同 |
| 损失函数 | CrossEntropyLoss |
| 优化器 | Adam, lr=1e-3 |
| Batch size | 256 |

## 6. 理论收敛分析

### 6.1 遗憾界 (Regret Bound)

设 π* 为专家策略（Q-score 贪心），π_BC 为 BC 训练后的策略。

BC 阶段的泛化误差：

```
E[1 - π_BC(a*|s)] ≤ ε_BC  (假设 BC 准确率 1-ε_BC)
```

标准行为克隆理论（Ross et al., 2011）给出：BC 策略的期望代价与专家之差在 O(T²ε) 内，其中 T 为决策步数。对于 T ≈ 80，若 ε ≤ 0.3（即 BC 准确率 ≥ 70%），模仿性能尚可接受。

### 6.2 PPO 改进界

PPO 微调后的策略 π_RL 相对于 BC 策略 π_BC 的性能提升由策略梯度定理保证：

```
J(π_RL) - J(π_BC) ≥ 0  (在合理步长和充分探索条件下)
```

收敛速度取决于 BC 初始化后价值函数的初始质量——这也是为什么我们强调 BC 阶段需要充分的专家数据。
